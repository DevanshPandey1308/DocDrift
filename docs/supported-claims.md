# Supported claims and checker behavior

Only the explicit forms below are extracted. Other natural-language claims are ignored rather than treated as true.

| Claim | Supported form | Verification source | Abstains when |
|---|---|---|---|
| Function parameters | `` `name(a, b)` accepts ... `` or `takes` / `has parameters` | Unique statically indexed Python function and the complete ordered list of parameter names | Missing or duplicate function, `*`/`**`/`/` calling-convention syntax, explicit `=default` optionality, or source parse problem |
| Explicit default | `The default [for] name is 30.`; Markdown tables with a `Default` header and a backticked identifier in the first cell; `` `name` (default: 30) `` / `` `name` (default 30) `` / `` `name` defaults to 30 ``; or a literal default in an inline call signature such as `` `fetch(timeout=30)` `` | Unique statically indexed Python parameter; signature defaults additionally require the named function to resolve uniquely | Ambiguous parameter/function name, missing symbol, dynamic default, or unsupported literal. Table defaults `required`, `-`, `—`, and `n/a` are skipped. |
| CLI flag | A backticked `--flag` or built-in short flag `-h` / `-V`, optionally in `Run the CLI with ...`; flags inside backticked third-party commands are extracted only to abstain safely | Literal `argparse` `add_argument`, Click `@click.option` on a command-decorated function, or literal `typer.Option` on a function decorated by a recognized `Typer` app command | Missing flags are false only if the literal is absent from all scanned source text, a recognized argparse/Click/Typer declaration exists, no computed/dynamic flag declaration exists, it is not `--help`, `-h`, `--version`, or `-V`, and either a likely renamed declaration shares a normalized stem / is within edit distance 3 or the line identifies this project's CLI (the CLI, this CLI, command line, a `[project.scripts]` name, or parser `prog`). Third-party command lines (`pytest`, `pip`, `docker`, `git`, `npm`) always abstain. Otherwise absence is unverifiable. |
| Environment name | Backticked all-capital name such as `` `API_KEY` `` | Literal key in `os.getenv`, `os.environ.get`, or `os.environ[...]`; all-capital names without underscores also need `environment variable`, `env var`, or `env:` in the same sentence | Missing names are false only if there is no word-boundary occurrence in scanned `.py`, `.toml`, `.yml` / `.yaml`, `.json`, `.env*`, or Dockerfile source text; no dynamic environment access exists; and at least two distinct literal environment names are read under the same first underscore-delimited project prefix, whose length is at least 3. Otherwise absence is unverifiable. Third-party names without a proven project namespace therefore abstain. |
| Environment default | A backticked all-capital identifier containing `_` followed by `defaults to` or `The default ... is ...` | Unique literal second argument to `os.getenv` or `os.environ.get` | No read, missing/non-literal default, or multiple reads. Numeric documentation matches a numeric string source default when their numeric values are equal (for example, `20` and `"20"`). |
| Repository path | Backticked relative path containing `/` with a recognized file extension, ending in `/`, or whose first segment is an existing directory; existing `.py` filename references remain supported | Resolve from repository root, the document directory, and their ancestors; existing files and directories are true. A missing path is false only when anchored: either its first segment is an existing directory at the scan root (or nearest documentation-side `pyproject.toml` root) and its parent directory exists below that root, or exactly one same-basename file elsewhere is evidence of a move. | Bare filenames and root-level missing files are unverifiable because they are not anchored to a repository directory. Move evidence is accepted only for a unique basename outside tutorial-like documents and when the basename (without extension) is not generic: `main`, `app`, `index`, `init`, `__init__`, `setup`, `conf`, `config`, `settings`, `version`, `__version__`, `utils`, `util`, `manage`, `wsgi`, `asgi`, `hello`, `example`, `demo`, `test`, `tests`, `readme`, `license`, `makefile`, or `dockerfile`. These common names occur independently across projects and are weak move evidence. Tutorial path segments (`tutorial`, `tutorials`, `guide`, `guides`, `user-guide`, `quickstart`, `getting-started`, `howto`, `howtos`, `cookbook`, `example`, `examples`, `learn`) likewise make a move ambiguous. Unresolved traversal and absolute paths abstain. Missing paths also abstain when they look like examples/instructions, placeholders, registry/image/action/package names, runtime/template paths, conventional build outputs, or references from history/release documents. Prose tokens such as `n/a`, `I/O`, `and/or`, `w/o`, and `TCP/IP`, URLs, whitespace, and wildcards are not path claims. |
| Python version | `Requires Python M.m or newer.`, `Python M.m+`, `Python M.m or higher/later`, or `Python >= M.m` | Nearest ancestor `pyproject.toml` from the documentation file through the scan root, using `requires-python = ">=M.m"`; comparison applies only to a project-level statement with a requirement/support cue | Parenthetical notes, feature/setting/version-reference notes, option/table rows, interactive usage examples, historical/release documents, and statements without a project-level cue are unverifiable. Missing metadata or any other requirement range grammar also abstains. |
| HTTP route | ``The GET `/health` endpoint exists.`` (also `route`; methods GET, POST, PUT, PATCH, DELETE, OPTIONS, HEAD) | Literal FastAPI `@app.get(...)` and equivalent method decorators, or Flask `@app.route(..., methods=[...])` on a statically constructed application | A matching static route is true even if another source file is incomplete. A missing method/path is false only if every route decorator and prefix in source scope was statically resolved and at least one route was indexed. Otherwise absence is unverifiable. Dynamic path or methods, unresolved router/blueprint mounting or prefix, duplicate contradictory declarations, or incomplete source indexing prevent absence conclusions. |

Function parameter claims require a complete, ordered name list, but names alone do not assert required/optional status or calling convention. Claims spelling `*args`, `**kwargs`, positional-only `/`, or a default in the signature abstain; use a separate supported default claim to verify a literal default. Click/Typer indexing is syntactic and does not import either framework. It covers the common decorator and `Option` forms above, not arbitrary APIs or dynamically generated commands. CLI checks establish flag declaration only; help text is not compared with arbitrary prose. Environment checks prove a recognized read only. A file's positive evidence points to its first actual source line.

Numeric defaults may include a recognized unit word (`seconds`, `second`, `s`, `ms`, `milliseconds`, `minutes`, `hours`, `bytes`, `KB`, or `MB`). The checker compares only the numeric value; it explicitly does not verify unit correctness or conversion. A numeric duration without an associated parameter name, such as “By default, requests time out after 30 seconds,” is not extracted. Markdown tables and signatures inside fenced code blocks are ignored. Claim extraction remains unchanged by the cautious path and Python-version verdict policies; a generated or tutorial path that is extracted may therefore remain visible as an unverifiable claim.

Default repository discovery skips hidden directories, `node_modules`, `venv`, `.venv`, `__pycache__`, `site-packages`, `dist`, and `build`; an explicitly supplied `--docs` or `--source` scope is still scanned. Text CLI output displays only the matched claim span (capped at 160 characters); JSON retains the full claim text and stable claim identifiers.

Route methods are normalized to uppercase. Flask GET declarations also include Flask's implicit HEAD and OPTIONS support. An exact path declared only for other methods is a contradictory finding. Direct static application routes can be checked. APIRouter and Blueprint routes are indexed but abstain because endpoint reachability and mount prefixes are not fully resolved; dynamic route declarations make route conclusions abstain for the scan.

Absence-based flag, environment-name, and route verdicts use the strict guard
lists in the table above and include either real near-miss declaration evidence
or an explanation naming the scanned source scope. Historical, negated, or
deprecated framing (`was`, `used to`, `previously`, `formerly`, `in v<N>`,
`deprecated`, negative forms such as `does not` / `never`, or a change arrow)
is unverifiable as a positive current claim. Defaults or
function claims explicitly attributed to another project/package/module/library
are also unverifiable rather than compared with same-named local symbols.

Verdicts are `true`, `false`, and `unverifiable`. `false` is used only where source evidence directly contradicts the supported claim. Missing symbols and ambiguous evidence generally abstain. Source parse errors are reported separately and make the CLI exit with operational error code 2.
